# 简历编排工具

粘贴一段岗位 JD，页面自动给项目库里的经历打分排序，选中后实时预览，一键导出 Word 或 PDF。

单文件网页，双击就能用，不依赖后端、不需要联网。

## 为什么做这个

投不同岗位时，简历该突出哪段经历是不一样的。手工改一版要十几分钟，还容易改漏。这个工具把「项目信息」和「岗位匹配」拆开：项目写一次，之后按 JD 重排即可。

## 怎么打开

双击 `index.html` 即可，不需要安装环境。首次使用先 `cp profile.example.js profile.js` 并填入个人信息。

详细步骤见 [使用说明.md](使用说明.md)。

## 怎么用

1. 把招聘要求整段粘进左侧输入框
2. 页面识别关键词，自动生成求职意向，并给项目打分排序、选中前两个
3. 点选或取消项目，点击顺序就是简历里的顺序（最多三个）
4. 右侧实时预览 A4 版面，字号与段间距会自适应，两个项目也能把一页铺满
5. 导出 Word（`.doc`，可在 Word 里继续编辑）或 PDF（浏览器打印，另存为 PDF）

## 面试评估与题库

打开右上的「面试评估」，左边给分、右边给题：

- 六个维度加权打分：岗位匹配度 30%、项目相关度 20%、技能覆盖 15%、成果量化 15%、项目深度 10%、版面规范 10%
- 评分完全本地计算，依据是 JD 关键词命中、项目得分、技能行覆盖、要点里的量化指标
- 题库四类：技术栈题（按项目用到的技术取，20+ 个技术点的参考答案）、项目题（每个项目 4 问，答案由简历要点拼出）、高频题（8 个，答案按当前意向生成）、AI 补充（可选，接模型后按简历和 JD 出题）
- 答案可编辑并持久化，可一键恢复默认，可导出成 Word 准备稿

## 编辑方式

简历本身是只读预览，改内容一律走右侧面板：

- 点简历上的任意模块（抬头 / 教育经历 / 项目 / 专业技能），右侧滑出对应表单，保存后立即重排
- 没填的关键信息在简历上显示为红色，左栏「待填内容」同步列出，点标签直接跳到那段表单
- 项目经历、专业技能支持「恢复默认」，回到自动汇总的文案

只读 + 表单一侧编辑，比整页 contenteditable 更稳：不会误触改字，也不会在拍照、选中文字时把排版改乱。

## 待填内容

页面里所有个人信息都走同一套占位符（`（姓名）`、`（学校）`、`（起止年月）`），左栏顶部把它们单独列成一份清单：

- 还没填的字段以标签列出，点标签直接跳到简历上那一处并聚焦
- 简历上未填的内容显示为虚线下划线，一眼能看出哪里还是空的
- 填完自动从清单消失，全部填完显示「都填好了」，避免漏填就导出

默认起止时间写成 `2023/09 - 2027/07`，教育经历右侧会顺带标出「2027 届」。

## 版面自适应

默认只放两个项目，页数靠排版撑起来而不是靠堆内容：

- 同一套内容，只选两个项目时整体字号放到约 11.5pt、行距 1.65；加到三个项目就自动收到 10.5pt 上下
- 段间距、行距、字号由一个参数统一驱动，不会出现「字很小但间距巨大」
- 正文底部固定落在距纸张下边缘约 2cm 的位置，下方不留大片空白，也不会把内容顶到纸边
- 导出 Word 时会把当前算出的字号与间距换算成 pt 写死，预览和 Word 版不会一个满一个空

## 一切都由 JD 生成

没有岗位预设按钮，页面只认 JD 文本：

| 生成项 | 依据 |
|---|---|
| 求职意向 | JD 里的岗位关键词（测试开发 / AI Agent / C++ / Go / 服务器运维 / 前端，都没命中就落到 Java 后端） |
| 项目组合 | 项目标签与 JD 关键词的重合度打分，取前两个；`distinct` 系数给「人人都在做」的项目降权 |
| 技能行顺序 | JD 命中最多的方向决定：AI 岗把「AI 与 Agent」提前，测试岗把「测试与质量」提前，运维岗把「服务治理 / 可观测性」提前 |
| 技能行内容 | 由选中的项目汇总技术栈，JD 里出现过的技术排到该行前面 |

同一个事实在不同岗位下会用不同的词描述，比如「Redis Pub/Sub 扇出」在后端岗归到「中间件能力」，在服务器岗归到「服务治理」。

没粘 JD 时先给一套通用组合（代码评审智能体 + ServerOps），想换自己点项目即可。

## 匹配逻辑

不是语义理解，是关键词计分：

```
得分 = (命中标签数 × 3 + 方向契合度 × 2) × 稀缺度 × 方向对口系数
```

- `tags`：项目涉及的具体技术词，和 JD 文本做匹配
- `direction`：项目所属方向（backend / ai / go / cpp / test / frontend / ops），第一个是主方向
- 方向契合度里，主方向按 1 倍算，次方向 0.5，第三 0.25——所有项目都挂着 backend，不给权重就分不出高下
- 主方向在 JD 里一次都没出现，整体乘 0.6；一个标签都没命中，再乘 0.4。这样靠 `http`、`并发` 这类通用词蹭分的项目不会挤掉真正对口的
- 英文关键词按词边界匹配，`reactor` 里的 `react` 不会被当成前端岗信号

好处是纯本地、稳定、可解释——每个项目的得分下面会列出命中了哪些词。

局限也很明显：写「熟悉消息队列」不会命中「中间件」这种同义但不同词的情况。要更准只能接大模型做语义匹配，代价是需要 key 且离线不可用。

## 个人信息怎么处理

仓库里**不含**任何个人信息。所有真实数据放在 `profile.js`，该文件已被 `.gitignore` 忽略。

首次使用：

```bash
cp profile.example.js profile.js
# 编辑 profile.js，填入自己的姓名、联系方式、教育经历
```

`index.html` 会尝试加载 `profile.js`，不存在则用占位文案，不影响功能。

## 项目库怎么改

在 `index.html` 末尾的 `PROJECTS` 数组里改，一条长这样：

```js
{
  id: "xxx",
  url: "https://github.com/you/xxx",
  name: "项目名",
  role: "核心开发",
  period: "2026/02 - 2026/04",
  direction: ["backend"],          // 所属方向，影响排序
  tags: ["java", "redis"],         // 与 JD 做关键词匹配
  stack: "技术栈",
  desc: "一句话描述",
  bullets: ["<b>小标题</b>：具体做了什么，解决了什么问题"]
}
```

## 已知限制

- Word 导出的是 HTML 格式的 `.doc`，部分 Word 版本首次打开会提示「文件格式与扩展名不一致」，点「是」即可；在 Word 里另存为 `.docx` 后不再提示
- PDF 依赖浏览器打印，边距由纸张设置决定，不同浏览器略有差异
- 匹配是关键词计分，不支持同义词与语义理解
- 只支持单套模板，没有多套版式可选
